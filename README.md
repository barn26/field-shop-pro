# FIELD SHOP PRO

Каталог товарів, кошик, замовлення, склад та завантаження електронних квитанцій про оплату.

## Структура

```
field-shop-pro/
├── server.js         # Express-сервер + REST API
├── package.json
├── data/
│   └── db.json        # "База даних" — товари, замовлення, налаштування, історія
├── uploads/            # Сюди зберігаються завантажені квитанції (фото/PDF)
└── public/
    └── index.html      # Клієнтський додаток (каталог + адмінка), звертається до API
```

## Запуск

```bash
cd field-shop-pro
npm install
npm start
```

Сервер підніметься на `http://localhost:3000` (порт можна змінити через `PORT=xxxx npm start`).

## Що є в комплекті

- **Каталог і кошик** — клієнти бачать товари, додають у кошик, оформлюють замовлення.
- **Квитанції про оплату** — одразу після оформлення замовлення клієнту пропонується
  завантажити фото/PDF квитанції (`POST /api/orders/:id/receipt`, зберігається у `uploads/`
  і роздається статично через `/uploads/...`).
- **Адмінка** (вхід за PIN, за замовчуванням `1234`, змінюється в налаштуваннях):
  - CRUD товарів, зміна залишків
  - перегляд замовлень, зміна статусу (нове → готове → видано), скасування з поверненням на склад
  - перегляд завантаженої квитанції прямо з картки замовлення
  - експорт/імпорт повної бази у JSON
- **База даних** — простий JSON-файл `data/db.json`, який сервер читає/пише при кожній зміні.
  Для продакшн-навантаження це можна легко замінити на SQLite/Postgres — структура API вже
  розділена по ендпоінтах, тож заміна сховища не торкнеться фронтенду.

## Важливо перед продакшн-використанням

- Замініть стандартний PIN адміністратора одразу після першого запуску.
- Перевірка PIN зараз побудована на простому порівнянні заголовка запиту — для публічного
  розгортання варто додати HTTPS і, за потреби, більш надійну автентифікацію (сесії/токени).
- Обмеження на завантаження квитанцій: до 10 МБ, формати JPG/PNG/WEBP/HEIC/PDF.
